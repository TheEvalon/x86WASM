- Intel SDM Vol. 3 §3.3.1 "Logical Address to Linear Address Translation" — outside 64-bit mode the processor addresses a **4 GiB** linear address space, so `segment base + offset` is formed modulo 2^32 and wraps at the top of the space instead of carrying into bit 32; in 64-bit mode the linear address space is the full 64 bits. `x86_mmu::linear_addr` masks to 32 bits and `x86_mmu::linear_addr64` does not; the canonical-address check is not modelled. ## Platform and devices

- PCI Local Bus Specification — Configuration Mechanism #1 (`CONFIG_ADDRESS` `0xCF8`, `CONFIG_DATA` `0xCFC`, Type 1 address, enable bit 31); Type 0 header Command register at `0x04` (bit0 I/O Space Enable, bit1 Memory Space Enable, bit2 Bus Master Enable). This emulator's i440FX-class host bridge stub stores/reads back only those three sticky bits (`0x0007`); other Command bits hardwired 0; decode/BM side effects deferred. Cache Line Size at config `0x0C` store/readback (reset `0x00`; no cache/burst side effects). Latency Timer at config `0x0D` store/readback (reset `0x00`; Mechanism #1 dword-align + `0xCFD` lane; no arbitration side effects). Status register at `0x06`: CapList (bit4 RO), Fast Back-to-Back Capable (bit7 RO), DEVSEL Timing (bits 10:9 RO), and RW1C error bits (MDPE/STA/RTA/RMA/SSE/DPE). Host bridge, PIIX ISA (`00:01.0`), PIIX IDE (`00:01.1`), PIIX USB UHCI (`00:01.2`), and PIIX ACPI (`00:01.3`) stubs hardwire CapList=0 / FastB2B=1 / DevSel=medium (`0x0280`); RW1C clear-on-write-1 implemented; devices do not latch error bits from real aborts yet. PIIX ISA bridge Command sticky mask mirrors the host bridge (`PCI_PIIX_ISA_COMMAND_MASK` = `0x0007` IO|MEM|BusMaster; decode side effects deferred); Status stub `PCI_PIIX_ISA_STATUS_STUB` = `0x0280`. PIIX IDE Command sticky mask is IO|BusMaster only (`0x0005`); MEM hardwired 0 (legacy IDE + BMIBA are I/O); BMIBA Command.IO enables a 16-byte BMIDE I/O noop register-file stub (command/status/PRD store/readback; no DMA engine). PIIX USB UHCI (`00:01.2`) Command sticky mask mirrors the host bridge (`PCI_PIIX_USB_COMMAND_MASK` = `0x0007` IO|MEM|BusMaster); UHCI BAR0 Command.IO enables a 32-byte UHCI I/O noop register-file stub (USBCMD/USBSTS/USBINTR/FRNUM/FLBASEADD/SOFMOD/PORTSC store/readback; no schedule/DMA engine); Status stub `PCI_PIIX_USB_STATUS_STUB` = `0x0280` CapList=0/FastB2B/DevSel=medium + RW1C (mirrors host/IDE/ISA; no abort signaling yet). PIIX ACPI (`00:01.3`) Command sticky mask mirrors the host bridge (`PCI_PIIX_ACPI_COMMAND_MASK` = `0x0007` IO|MEM|BusMaster; ACPI PM I/O / decode side effects deferred); Status stub `PCI_PIIX_ACPI_STATUS_STUB` = `0x0280` CapList=0/FastB2B/DevSel=medium + RW1C (mirrors host/IDE/ISA/USB; no abort signaling yet)
- PCI Local Bus Specification Revision 3.0 §3.2.2.3.2 "Configuration Mechanism #1" — the access-width rules, which this tree now implements without an escape hatch. CONFIG_ADDRESS bit 31 Enable, bits 30:24 "reserved, read-only, and must return 0's when read", bits 23:16 Bus Number, 15:11 Device Number, 10:8 Function Number, 7:2 Register Number, 1:0 read-only zero. "Anytime a host bridge sees a full DWORD I/O write from the host to CONFIG_ADDRESS, the bridge must latch the data into its CONFIG_ADDRESS register"; "Any other types of accesses to this address (non-DWORD) have no effect on CONFIG_ADDRESS and are executed as normal I/O transactions on the PCI bus" — on this machine nothing claims those transactions, so they read as ISA open bus and drop writes. A host access is translated to a configuration cycle when it "falls inside the DWORD beginning at CONFIG_DATA", which is what makes `0xCFD`/`0xCFE`/`0xCFF` select byte lanes inside the latched register rather than being separate registers; "In both Type 0 and Type 1 translations, byte enables for the data transfers must be directly copied from the processor bus". Footnote 15: "If the Device Number field selects an IDSEL line that the bridge does not implement, the bridge must complete the processor access normally, dropping the data on writes and returning all ones on reads". §3.2.2.3.4 "Master-Abort" gives the same all-ones / dropped-write completion for a configuration cycle no device claims. Covered by `crates/devices/tests/pci_config_access_widths.rs` and `docs/pci-r3-config-access.md`
- PCI Local Bus Specification — reserved configuration fields are read-only and return zero. Applied to the PAM registers below (Table 2 bits `[7, 6, 3, 2]` and `PAM0[3:0]`): reserved bits are masked on write and read back as zero rather than storing what the guest wrote
- PCI Firmware Specification / BIOS Boot Specification — PC-compatible expansion ROM header: byte 0–1 signature `0x55 0xAA`, byte 2 the initialization size in 512-byte blocks, byte 3 onwards the entry point, and a byte-wise sum over the initialization size that must be zero modulo 256. Legacy placement is `0xC0000`–`0xDFFFF` scanned on 2 KiB boundaries, with the video BIOS conventionally at `0xC0000`. This tree implements validation and placement in `firmware_interface::prepare_option_rom` / `Machine::map_option_rom`, plus a host-driven far call to offset 3 via `Machine::invoke_option_rom_entry` / `map_and_invoke_vga_option_rom` (`docs/firmware-r7-option-rom-invoke.md`). **Not:** the PCI expansion-ROM BAR (`0x30`), ROM discovery scan loop, PnP header at offset `0x1A`, BEV/BCV entries, or SeaBIOS POST option-ROM dispatch.
